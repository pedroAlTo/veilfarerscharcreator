Date: 2026-07-19

PURPOSE
-------
Code-only hotfix for authenticated Player/Keeper reload loops, duplicate Player characters, pending-to-final Character ID migration, Character ID placement and repeated Keeper Firebase initialization.

DEPLOY
------
1. Create or use a clean test branch based on the intended current base.
2. Replace the branch contents with the contents of VeilFarers_Portal_v59.50.zip. index.html must remain at repository root.
3. Commit and push the complete release.
4. Confirm Netlify dependency installation uses registry.npmjs.org.
5. Hard-refresh the Deploy Preview after publication.
6. Sign out and sign in once before authenticated QA.

DO NOT
------
- Do not deploy project-wide Firestore Rules merely to test this code hotfix.
- Do not copy only player-tool.html or keeper-tool.html; the fix also changes character-registry.js, character-sync-adapter.js, portal.js and portal.css.
- Do not relax the portal CSP for Segment/Bugsnag Deploy Preview analytics.
- Do not modify assets/3d-dice.

MANDATORY QA
------------
PLAYER TOOL
1. Sign in and open Player Tool.
2. Confirm the main loading shell completes once and does not restart.
3. Open the same Vault character repeatedly; one Player tab must remain.
4. Refresh Vault; the open character should update in place.
5. Complete/sync a pending character; PENDING-* must become one VF-###### record.
6. Change current HP/Stress before a build refresh and confirm current values remain.

CHARACTER ID
7. Confirm the current VF-###### appears in shared navigation.
8. Confirm there is no fixed bottom-corner Character ID callout.

KEEPER TOOL
9. Sign in and open Keeper Tool.
10. Confirm tables load once, no page reload loop occurs and no Firestore host-override warning appears.
11. Connect to a disposable table, disconnect/reconnect and verify only one live listener is reflected in behavior.

CONSOLE
12. Segment/Bugsnag ERR_BLOCKED_BY_CLIENT under cdp/?deployID are Netlify preview UI noise. Investigate only errors that reference VeilFarers files, Firestore or /api endpoints.

ACCEPTANCE
----------
Merge only after Player and Keeper remain stable for several minutes while authenticated and repeated Vault/table operations produce no reload.
