# VeilFarers Portal v59.50 — Identity, Vault and Table Security Notes

## Security boundary unchanged

v59.50 is a client reliability and identity-consistency hotfix. It does not weaken or replace the v59.49 authorization model:

- Netlify Identity verifies the general user.
- `/api/character-vault` enforces Character Vault ownership server-side.
- `/api/firebase-auth-token` bridges the verified Netlify UID into Firebase Authentication.
- Firestore Rules remain the authorization boundary for real-time table documents.
- `/api/table-api` remains the server boundary for table creation, membership, invitations and password administration.

## Character identity

A Player Tool character is keyed by permanent `characterId`, not display name or tab index. During deferred allocation:

1. the local record may temporarily use `PENDING-*`;
2. the registry obtains `VF-######` from the authenticated allocator;
3. the registry emits the old pending ID as `previousCharacterId`;
4. Player Tool removes the pending owner and its pending drone records;
5. the final record is written once under `VF-######` while local runtime tracks remain intact.

The fallback fingerprint is used only to collapse an otherwise identical pending/final pair already left by earlier builds. Two final IDs are never merged merely because their names match.

## Reload-loop removal

Authenticated Vault refreshes previously triggered a registry event followed by `location.reload()` in Player Tool and Keeper Tool. On the next load the authenticated Vault refreshed again, creating a loop. v59.50 removes that reload path. Data is updated through storage plus explicit custom events.

This is not an authorization change; it prevents repeated initialization and duplicate client state.

## Keeper Firebase initialization

Keeper Tool now:

- waits for an authenticated Keeper user before listing tables;
- shares one Firebase initialization promise across simultaneous callers;
- calls Firestore settings with `{ ignoreUndefinedProperties: true, merge: true }`;
- maintains one active session snapshot subscription and unsubscribes it before connecting to another table.

## Netlify Deploy Preview diagnostics

Console requests to:

```text
cdn.segment.com
sessions.bugsnag.com
cdp/?deployID=...
```

with stack frames such as `_app.tsx`, `next.js` or Netlify UI modules are generated by the Netlify Deploy Preview interface. `ERR_BLOCKED_BY_CLIENT` normally indicates an ad/privacy blocker. They are not VeilFarers authentication, Firebase or CSP failures and are not added to the portal allowlist.

A relevant application failure will instead reference a VeilFarers file or endpoint such as:

```text
player-tool.html
keeper-tool.html
character-registry.js
/api/character-vault
/api/firebase-auth-token
/api/table-api
firestore.googleapis.com
```

## Firestore Rules boundary

The included `firestore_v59.50.rules` is unchanged in substance from v59.49. Firebase Rules are project-wide, not branch-specific. Do not deploy a different Rules model solely to test this hotfix against the production Firebase project.

## Secrets

The deploy requires the existing Netlify variables and introduces no new secret:

```text
FIREBASE_SERVICE_ACCOUNT_JSON
FIREBASE_API_KEY
FIREBASE_AUTH_DOMAIN
FIREBASE_PROJECT_ID
FIREBASE_STORAGE_BUCKET
FIREBASE_MESSAGING_SENDER_ID
FIREBASE_APP_ID
FIREBASE_MEASUREMENT_ID
FIREBASE_PUBLIC_TABLE_DIRECTORY=false
```

`FIREBASE_SERVICE_ACCOUNT_JSON` must remain Functions-only/server-only and must never be committed or returned by `/api/firebase-config`.
